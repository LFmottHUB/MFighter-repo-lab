Instalación paso a paso

Crea una carpeta de laboratorio

Abre RaGEZONE, inicia sesión o regístrate, localiza el post del remake en Python y descarga únicamente el adjunto asociado a esa publicación. Conserva el ZIP original sin modificar.

Analiza y extrae el archivo

Examina el ZIP con Microsoft Defender o VirusTotal. Después descomprímelo en una carpeta como C:\MiniFighterLab\MiniFighterPython.

Instala Python 3.12.10

Descarga el instalador oficial de Windows. Durante el asistente activa Add python.exe to PATH y completa la instalación para tu usuario.

Comprobación en PowerShell
py -3.12 --version python --version

Abre una terminal dentro del proyecto

En el Explorador de archivos entra a la carpeta raíz, haz clic en la barra de dirección, escribe powershell y pulsa Enter.

cd C:\MiniFighterLab\MiniFighterPython dir

Crea y activa el entorno virtual

El entorno mantiene Arcade y las demás librerías separadas del Python general de tu computadora.

py -3.12 -m venv .venv .\.venv\Scripts\Activate.ps1
Si PowerShell bloquea la activación, abre CMD y usa: .venv\Scripts\activate.bat.

Instala las dependencias

Actualiza pip. Si el paquete trae requirements.txt, instálalo; de lo contrario instala la versión de Arcade indicada por el autor.

python -m pip install --upgrade pip # Usa este comando si existe requirements.txt python -m pip install -r requirements.txt # Si no existe, instala Arcade directamente python -m pip install arcade==3.3.3

Comprueba Arcade antes de abrir el juego

Este comando debe mostrar una versión sin lanzar excepciones. Si falla, revisa la pestaña Problemas.

python -c "import arcade; print(arcade.__version__)"

Prueba primero el modo individual

Ejecuta el archivo principal desde la raíz del proyecto. No lo abras haciendo doble clic: así podrás leer cualquier error de la terminal.

python src\main.py

Prueba el servidor multijugador local

Abre dos terminales con el entorno activado. Inicia primero el servidor y luego el cliente. Mantén la dirección en 127.0.0.1.

Abre la caja de herramientas opcional

La ruta exacta puede variar entre versiones. Busca AllInOneMFOToolbox.py dentro de la carpeta de herramientas y ejecútalo desde la terminal.

Flujo recomendado para aprender sin romper el proyecto

Primero consigue una ejecución limpia; después crea una copia de trabajo y modifica componentes pequeños. El remake es un proyecto en desarrollo, por lo que contenido presente en los recursos puede no estar implementado todavía.

Congela el entorno funcional

Cuando el juego abra, guarda las versiones instaladas con python -m pip freeze > requirements-local.txt. Así puedes reconstruir el entorno más adelante.

Usa control de versiones

Inicializa Git solo en tu copia de código. Excluye .venv, archivos temporales y recursos que no tengas derecho a redistribuir.

Prueba por capas

Orden sugerido: modo individual → carga de recursos → guardado → servidor local → segundo cliente. Esto reduce la cantidad de causas posibles ante un fallo.

Separa código y recursos

No conviertas ni sobrescribas archivos dentro de assets durante las primeras pruebas. Exporta con la Toolbox hacia otra carpeta.

Documenta cada personaje

Para implementar contenido registra animaciones, estados, colisiones, velocidad, daño y entradas. Que un sprite exista no significa que su lógica esté terminada.

Mantén localhost

Para aprender sockets no necesitas publicar el servidor. Usa 127.0.0.1; una prueba en red local debe hacerse después y con reglas de firewall explícitas.

Instalación paso a paso

Comprueba y activa la virtualización

Abre Administrador de tareas → Rendimiento → CPU. Si aparece deshabilitada, actívala desde BIOS/UEFI antes de instalar la máquina virtual.

Crea una máquina virtual limpia

Instala VirtualBox u otra solución fiable, crea una VM de Windows y toma una instantánea llamada Windows limpio. Para una revisión rápida también puedes usar Windows Sandbox, sabiendo que elimina todo al cerrarse.

Limita la red y las integraciones

En la primera ejecución usa red deshabilitada o NAT, evita carpetas compartidas y desactiva el portapapeles bidireccional. No abras puertos del router.

Obtén el repack desde el hilo original

Abre la página 4 de RaGEZONE, localiza el post #66 y descarga el adjunto correspondiente. Es posible que necesites iniciar sesión. No uses mirrors publicados por cuentas desconocidas.

Analiza el paquete antes de ejecutarlo

Escanea el ZIP y, después de extraerlo, analiza por separado Server.exe, MFStart.exe y las DLL. Guarda los hashes y conserva una copia intacta del paquete.

Get-FileHash .\Server_MF\Server.exe -Algorithm SHA256 Get-FileHash .\Client\MFStart.exe -Algorithm SHA256

Instala MariaDB dentro de la VM

Usa el instalador MSI oficial, define una contraseña exclusiva para el laboratorio y deja el servicio configurado para iniciar con Windows. No reutilices contraseñas reales.

Comprueba que el cliente responde
mariadb --version

Crea una base y un usuario local

Abre el cliente de MariaDB. Los nombres siguientes son ejemplos seguros; puedes cambiarlos, pero deberás usar los mismos datos en config.ini.

mariadb -u root -p CREATE DATABASE minifighter; CREATE USER 'mf_local'@'127.0.0.1' IDENTIFIED BY 'CAMBIA_ESTA_CLAVE'; GRANT ALL PRIVILEGES ON minifighter.* TO 'mf_local'@'127.0.0.1'; FLUSH PRIVILEGES;

Importa el archivo SQL del repack

Dentro del cliente MariaDB selecciona la base y usa SOURCE. En Windows utiliza barras diagonales normales en la ruta.

USE minifighter; SOURCE C:/MiniFighterLab/MiniFighterS3/Database/database.sql; SHOW TABLES;
Si el archivo SQL tiene otro nombre o ubicación, usa la ruta real que aparece en el paquete.

Reglas de laboratorio para Season 3

Esta ruta reproduce una arquitectura antigua con binarios de terceros y una base persistente. La seguridad y la capacidad de volver atrás son parte del procedimiento, no pasos opcionales.

Instantáneas por etapa

Crea una al instalar Windows, otra después de MariaDB y una tercera cuando el login funcione. Nómbralas con fecha y estado.

Red mínima

Durante la ejecución usa red desconectada o NAT y 127.0.0.1. No configures port forwarding ni una IP pública.

Credenciales desechables

La contraseña de MariaDB y la cuenta del juego deben existir solo dentro de la VM. No reutilices correos, usuarios o claves personales.

Arranque y cierre ordenados

Arranque: MariaDB → servidor → launcher. Cierre: cliente → servidor → MariaDB o apagado de la VM. Evita interrumpir una escritura SQL.

Un cambio por prueba

Registra valores originales y nuevos de cada INI. Antes de tocar tablas, exporta la base o clona la instantánea.

Fuente ≠ binario

La carpeta de código permite estudiar la lógica, pero no demuestra que todos los EXE y DLL incluidos se hayan compilado desde ella.
